Tu agente vive donde lo construyas. PREMORTEM es el banco de pruebas al que se conecta antes de tocar Stripe: lo rompe en mundos adversos, guarda la evidencia y propone la corrección.

Tres formas de conectar un agente

Construido

Prompt + modelo

Registras las instrucciones de tu agente. PREMORTEM lo ejecuta con Claude contra las herramientas simuladas, con el prompt cifrado.

POST /api/agent-versions { driver: "anthropic", systemPrompt: "…" }
Construido

Desde un agente de código (MCP)

Claude Code o cualquier cliente MCP evalúa, lee el reporte, pide la corrección y compara versiones sin salir del editor.

claude mcp add premortem \ -- pnpm -s mcp

Concepto, no una integración oficial. Los constructores de apps como Lovable generan el código de tu app. La app llama a la API pública de PREMORTEM (/api/agent-versions, /api/runs, /api/compare) igual que cualquier front. El botón de publicar queda bloqueado mientras haya violaciones de seguridad.

1

Exportar

El prompt de tu agente, desde n8n, LangGraph, Vercel AI SDK o tu propio código.

2

Registrar

POST /api/agent-versions crea una versión inmutable y cifrada.

3

Evaluar

POST /api/runs con los mundos del paquete.

4

Comparar

GET /api/compare contra la versión en producción.

5

Decidir

Si aparece una violación nueva, el merge o el despliegue se bloquea.

# .github/workflows/agent-robustness.yml (ejemplo)
- name: PREMORTEM · probar el prompt del agente
  run: |
    AGENT=$(curl -sf -X POST "$PREMORTEM_API/api/agent-versions" -H "Authorization: Bearer $PREMORTEM_TOKEN" \
      -H "Content-Type: application/json" \
      -d "$(jq -n --rawfile p agents/refunds.md '{driver:"anthropic",label:"pr-'$GITHUB_SHA'",systemPrompt:$p}')" | jq -r .id)
    RUN=$(curl -sf -X POST "$PREMORTEM_API/api/runs" -H "Authorization: Bearer $PREMORTEM_TOKEN" -H "Content-Type: application/json" \
      -d '{"caseVersionId":"'$CASE_ID'","agentVersionId":"'$AGENT'","scenarioIds":["baseline","duplicate_identity","commit_ack_lost","permission_revoked"],"seed":7}' | jq -r .run_id)
    # esperar y comparar contra el run de la versión en producción
    curl -sf "$PREMORTEM_API/api/compare?a=$PROD_RUN&b=$RUN" -H "Authorization: Bearer $PREMORTEM_TOKEN" \
      | jq -e '.matrix | map(select(.change == "empeoró")) | length == 0'

El mismo patrón funciona en cualquier plataforma que permita exportar el prompt o llamar a una URL. El token es el de un usuario de servicio con su propio workspace, guardado como secreto del pipeline.

La memoria: cómo mejora el agente versión a versión

Cada versión queda guardada con su evaluación. Nada se sobrescribe: la historia es la evidencia de que el agente mejoró.

v1 · prompt original
1 / 4
  • Busca clientes por nombre
  • Reintenta con otra clave
  • Siempre dice “listo”
v2 · tras 3 lecciones
4 / 4
  • 3 aprobados y 1 detención correcta
  • 0 violaciones de seguridad
  • Derivada de v1, con diff guardado
v3 · cuando cambie el modelo
?
  • Misma suite y misma semilla
  • Si algo empeora, se bloquea
  • Cada fallo nuevo se suma a la suite
